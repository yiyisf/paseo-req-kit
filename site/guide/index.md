# req-kit 是什么

req-kit 是运行在 [Paseo](https://paseo.sh) 上的一套**规范化需求开发体系**。它专为非专职开发、但有一定技术背景的同事（测试、产品经理、项目经理）打造，把一个需求从"我想要……"稳健推进到"可以验收"：

::: tip 核心价值理念
- **对话即开发**：你在 Paseo 对话里输入 `/req` 和一句话，AI 用深度访谈的方式和你把需求谈清楚，写成标准需求说明（`spec.md`）请你确认。
- **后台流水线**：确认后，一组 AI Agent 在后台依次完成方案设计、方案审核、代码实现、交叉评审、服务启动、功能验证、缺陷修复和完成报告。
- **透明可追溯**：进展、需要你决定的业务问题和最终结论都发回同一个对话；你再按验收标准逐条验收。
- **安全不越界**：整个过程只在本地提交代码，不连生产环境，合并和上线始终由人最终决定。
:::

## 适合谁

| 角色 | 核心使用场景 | 获得收益 |
| :--- | :--- | :--- |
| **测试同事** | 发现缺陷或小改进后直接立项推进，或作为测试阶段负责人接手 | 避免反复沟通，按规范提测说明在指定环境严密验证 |
| **产品经理** | 把脑海中的需求方案谈清楚，迅速拿到可运行的原型或功能 | 需求不再被脑补，得到详尽、讲人话的验收报告 |
| **项目经理** | 通过 `req digest` 洞察所有需求进展，企业 IM 自动化通知 | 进度实时可视化，卡点与风险随时掌握 |
| **开发同事** | 负责环境安装、一键项目接入（`/req-setup`）与最终合并 | 免去写琐碎小需求的精力，只专注于核心架构与最终 Merge Review |

## 它不做什么

::: warning 安全与合规边界
- **不私自合并与上线**：不自动合并到主分支，不自动推送到远程仓库，不连接生产环境，不使用生产凭据。
- **不替代最终人工代码审查**：交付报告附录明确标明了本地分支、提交记录与完整变更文件列表，由研发负责人最终审核。
- **不追求通用的编码提效**：专注于解决业务场景落地与可信验收，详见 [范围与取舍](/reference/scope)。
:::

## 支持的环境

| 运行环境 | 版本与规格要求 | 状态与说明 |
| :--- | :--- | :--- |
| **Paseo** | `0.11` 或更新 | Paseo daemon 在后台运行；网页版或桌面版客户端均可 |
| **Node.js** | `22.x` 或更新 | 引擎运行与安装器依赖 |
| **操作系统** | macOS、Linux、Windows (PowerShell / Git Bash / WSL) | 跨平台支持 |
| **Agent 支持** | Claude Code、Codex、OpenCode、Pi 等已在 Paseo 登录的 Agent | 建议 Builder 与 Reviewer 配置不同模型实现交叉把关 |
