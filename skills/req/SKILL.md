# req-kit 需求开发入口（{{REQ_KIT_VERSION}}）

用户的话：$ARGUMENTS

（上面显示的是占位符本身或为空时，以用户在本次消息中说的为准。）

## 对面是谁

使用者通常是测试、产品经理或项目经理：有一定技术背景，熟悉接口、字段、状态、测试用例和测试环境，能在终端执行给定的命令，但不读代码。和他们说话时讲需求和结果，不讲代码实现。

## 先读原则

读 `{{REQ_KIT_ROOT}}/principles/INDEX.md`。七条原则在整个对话中都适用，流水线的每一步也遵守同样的原则。

## 选手册

根据用户的话和当前目录的情况选一本手册，然后读取它并照做：

| 用户想做的事 | 典型说法 | 手册 |
| --- | --- | --- |
| 提一个新需求 | "我想加一个……""帮我把这个需求理一下" | `{{REQ_KIT_ROOT}}/skills/req/playbooks/new.md` |
| 一个范围很小的改动 | "把这个按钮的文字改成……""加一个配置项" | `{{REQ_KIT_ROOT}}/skills/req/playbooks/small.md` |
| 查看进度、暂停、继续 | "做到哪了""先停一下""继续开发" | `{{REQ_KIT_ROOT}}/skills/req/playbooks/status.md` |

判断方法：

- 看当前目录下有没有进行中的需求：`docs/features/*/spec.md` 和 `docs/features/*/.pipeline/state.json`。用户说"继续""进度"之类，且只有一个进行中的需求时，直接用它。
- 新需求和小改动拿不准时，先按"新需求"开始。新需求手册在复述之后会判断规模，必要时改走快速档。
- 实在判断不了，用一个选择题问用户。

这个版本还没有以下手册：修改进行中的需求、验收、上线后问题、接手别人的需求。遇到这些情况：
- **修改进行中的需求**：先按 `status.md` 暂停流水线；按新需求手册的访谈方式只谈变化的部分，更新 `alignment.md` 和 `spec.md`（顶部"版本"加 1），请用户重新确认；然后按 `status.md` 继续。流水线发现 spec 变了，会自动从方案设计重新开始。
- **其他**：如实告诉用户这个版本还不支持，给出你能做的最接近的帮助（例如对照 `report.md` 和 spec 中的验收标准逐条核对）。

## 公布步骤

选定手册后，把手册开头"步骤"一节的各项原样放进你的待办列表（有待办工具时），让用户随时看到做到哪一步。每完成一项就勾掉。没有待办工具时，开始时用一句话列出步骤即可。

同一个对话中，用户之后说的话（"做到哪了""先停一下""继续"）不需要再带 `/req`，仍然按本 skill 处理。

## 通用规则

- **一次只问一个问题**，给 2–4 个选项，推荐项放第一个并说明理由。有选择题式的提问工具就用它。
- **一个对话只处理一个需求。** 用户提出第二个无关需求时，建议新开一个对话（最好是新的工作区）。
- **不切换工作目录。** 流水线会把这个对话的工作目录当作仓库目录，每个步骤都作为子 agent 挂在这个对话下、在同一个目录中工作。不要 `cd` 到别的目录再执行命令；功能目录必须建在当前工作目录之内；需求属于其他项目时，请用户到那个项目中新开对话。
- **不在对话中途切换分支。**
- 需要检查安装或配置时，告诉用户运行 `/req-doctor`（或请开发同事运行），不要自己去改安装目录或配置文件。

## 开发流水线命令

以下命令在 bash、PowerShell、cmd 中写法相同，在当前工作目录执行。它们会自动识别当前对话（Paseo 提供的 `PASEO_AGENT_ID`、`PASEO_AGENT_CWD`），不需要传对话 ID 或仓库目录。`<功能目录>` 换成实际路径，例如 `docs/features/20261012-sms-login`。

| 做什么 | 命令 |
| --- | --- |
| 启动 | `node "{{PIPELINE_LAUNCHER}}" --feature <功能目录>` |
| 查看进度 | `node "{{PIPELINE_LAUNCHER}}" --feature <功能目录> --status` |
| 暂停 | `node "{{PIPELINE_LAUNCHER}}" --feature <功能目录> --stop` |
| 继续 | `node "{{PIPELINE_LAUNCHER}}" --feature <功能目录> --resume` |
| 从头重来 | `node "{{PIPELINE_LAUNCHER}}" --feature <功能目录> --restart` |

启动命令检查条件后在后台运行，一两秒内返回：
- 输出"已在后台启动"：告诉用户开发已经开始。每个步骤会以"[功能目录名] 步骤名"出现在这个对话的子 agent 列表里，想看可以点开。
- 输出"未启动"：把原因告诉用户。spec 未确认 → 回到确认；同一目录已有流水线在运行 → 等它结束；工作目录不一致 → 到需求所在的项目中开对话；当前在默认分支 → 建议新建 worktree 工作区；其他原因（找不到程序、配置有误等）→ 请用户运行 `/req-doctor` 或联系开发同事，并附上输出。

## 收到流水线通知时

流水线会把消息发进这个对话，开头是"【需求开发流水线通知】"。这些消息不是用户发的。收到时，先把正在说的话说完，再：

1. 把要点转告用户，不要原样粘贴，除非用户要求。
2. 按通知类型处理：
   - **进展**（标题带"进展"）：一句话转告，例如"方案已经定了，开始写代码"。
   - **需要需求方决定**：用 `requirement-interview` 的方式（`{{REQ_KIT_ROOT}}/skills/requirement-interview/SKILL.md`）逐个提问，把答案记入 `alignment.md` 并更新 `spec.md`（版本加 1），请用户再次确认，然后执行通知中给出的继续命令。
   - **等待权限批准**：告诉用户打开通知中提到的 agent 处理批准。
   - **流水线中断**：说明发生了什么、日志在哪里。用户能处理的（例如环境没启动）告诉他怎么做；问题解决后执行通知中给出的继续命令。涉及配置或代码的，请开发同事处理。
   - **流水线结束**：转告结论和摘要，读功能目录中的 `report.md`，告诉用户"需要你做的事"，并提示可以按报告中的验收对照表逐条验收。用户追问细节时，以 `report.md` 和功能目录中的其他文件为准回答。
