# 手册：接手需求

需求方要接手别人提出的需求，或者隔了一段时间回来想知道一个需求的情况。讲清现状和待决事项，然后转入对应的手册。

## 步骤

1. 找到需求
2. 读全部记录
3. 讲清现状
4. 转入下一步

## 1. 找到需求

执行 `node "{{PIPELINE_LAUNCHER}}" --list`，列出这个项目所有工作区中的需求。根据需求方说的名称或描述找到它；拿不准时把候选列出来请对方选。

需求在另一个工作区时，告诉需求方：后续的修改、继续开发、验收都要在那个工作区的对话中进行（流水线的步骤挂在发起的对话下，并在那个目录里工作）。可以在 Paseo 中打开那个工作区，新开一个对话后再输入 `/req 接手 <需求名称>`。这一步只读文件，可以在当前对话完成。

## 2. 读全部记录

按顺序读功能目录中的文件（存在哪个读哪个）：

1. `spec.md`：要做什么、版本、档位
2. `changes.md`：改过几次、为什么
3. `alignment.md`：访谈中定下的事和假设
4. 状态：执行"查看进度"命令（只有在需求所在的工作区才能得到准确的运行状态；在别的工作区时，读 `.pipeline/state.json` 和 `progress.md`）
5. `handoff.md`（提测说明，有就读）、`report.md`、`acceptance.md`：改了什么、结论、遗留问题、验收结果
6. `decisions.tsv`：`needs_human` 为 `yes` 且还没有被确认的决定

## 3. 讲清现状

按 `{{REQ_KIT_ROOT}}/skills/result-report/SKILL.md` 的"接手"场景说明，不超过 10 行：

- 这个需求要做什么（一两句）
- 现在在哪个阶段：对齐中 / 已确认未开发 / 开发中 / 中断 / 等待决定 / 研发完成待测试验证 / 待验收 / 已验收
- 待决事项：需要回答的问题、需要确认的决定、遗留问题
- 建议的下一步

需求方追问细节时，以文件为准回答，并说明出处。

## 4. 转入下一步

按需求方的选择转入对应手册（在需求所在的工作区中）：

| 情况 | 手册 |
| --- | --- |
| 还在对齐、spec 未确认 | `new.md` 从第 5 步继续访谈（先读 `alignment.md`，已经定下的不要再问） |
| 要改需求 | `change.md` |
| 开发中断或暂停，要继续 | `status.md` 的"继续" |
| 等待需求方决定 | 用访谈的方式回答问题，更新 spec 后继续（见 `/req` 中"收到流水线通知时"） |
| 研发完成，待测试验证 | `verify.md`（测试同事接手测试也走这里） |
| 已完成，待验收 | `accept.md` |
