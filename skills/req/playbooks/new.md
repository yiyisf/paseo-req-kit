# 手册：新需求

## 步骤

1. 确认工作区
2. 阅读项目资料
3. 听需求并复述
4. 判断规模，确定档位
5. 访谈
6. 写需求说明并自查
7. 请需求方确认
8. 启动开发

## 1. 确认工作区

每个需求最好在自己独立的 worktree 工作区中进行：流水线会在这个对话的工作目录里运行几个小时并提交代码，独立的工作区不影响项目主目录，几个需求也可以同时进行。

运行 `git rev-parse --git-dir --git-common-dir` 和 `git branch --show-current`：

- **两个路径相同（项目主目录）**：说明上面的好处，建议在 Paseo 中为这个需求新建工作区再开始：**New workspace** → 选择这个项目 → **Isolation** 选 **New worktree** → 起点选主分支（如 `origin/main`），然后在新工作区的对话里重新输入 `/req`。用户坚持在这里继续也可以，到第 4 步之后新建功能分支（见下）。
- **两个路径不同（已在 worktree 中）**：直接继续，使用当前分支，不要再新建分支。
- **不是 git 仓库**：直接继续，跳过所有分支相关的操作。

## 2. 阅读项目资料

按 `{{REQ_KIT_ROOT}}/skills/requirement-interview/SKILL.md` 中"开口之前"一节阅读项目资料。能从代码和文档得到的答案不拿去问。

## 3. 听需求并复述

请用户用自己的话讲一遍。用两三句话复述你的理解，确认后再往下。

然后确定功能目录：`docs/features/<YYYYMMDD>-<英文短名>/`，例如 `docs/features/20261012-sms-login/`，英文短名用小写字母和连字符。创建该目录。

只有在项目主目录中进行、且当前在默认分支（如 `main`、`master`）上时，才新建并切换到分支 `feature/<功能目录名>`。不要动工作区里已有的、与本需求无关的改动。流水线不会在默认分支上提交代码。

## 4. 判断规模，确定档位

向用户推荐一个档位，说明理由，请用户确认：

- **快速档**：小改动，影响面窄，不涉及数据结构、权限、计费或对外接口。例如改文案或样式、加一个配置项、调整一个字段的显示。之后按 `small.md` 手册继续（从它的"访谈"一步开始）。
- **标准档**：其他情况，继续本手册。

拿不准时选标准档。访谈中发现需求比预想的复杂（涉及数据、权限、多个角色或流程），改为标准档并告诉用户。

## 5. 访谈

按 `{{REQ_KIT_ROOT}}/skills/requirement-interview/SKILL.md` 进行访谈，边谈边写 `alignment.md`，直到满足其中"标准档"的结束条件。

## 6. 写需求说明并自查

按 `{{REQ_KIT_ROOT}}/skills/spec-writing/SKILL.md` 写 `spec.md`（顶部 `- 档位：标准`），验收标准按 `{{REQ_KIT_ROOT}}/skills/acceptance-criteria/SKILL.md` 写，然后按其中的清单自查。

## 7. 请需求方确认

按 `spec-writing` 中"确认"一节：给出 10 行以内的摘要，确认后把状态改为"已确认"并提交。

## 8. 启动开发

告诉用户需求说明保存在哪里，然后问是否现在开始开发。说明三点：开发在后台进行，通常需要几个小时；过程中不需要盯着；有进展、需要他们决定或完成时，会在这个对话里通知。

用户同意后，执行 `/req` 中的"启动"命令。用户没有同意时，告诉他们之后随时说"开始开发"即可。
