# 手册：查看进度、暂停、继续

## 步骤

1. 找到功能目录
2. 执行对应的命令
3. 转告结果

## 1. 找到功能目录

- 这个对话里已经谈过的需求：用它的功能目录。
- 否则执行"列出需求"命令。当前工作区只有一个开发相关的需求时用它；有多个时，把它们（标题、阶段）列出来请用户选择。
- 需求在另一个工作区：暂停、继续、从头重来都要在那个工作区的对话中进行，请用户到那里操作。查看进度可以在这里读它的 `progress.md` 回答。例外：用"启动（自动新建工作区）"开发的需求，研发完成后可以在这里开始测试验证（见 `verify.md`）。
- 一个也没有：告诉用户当前项目里没有找到需求，问他是不是想提一个新需求，或者需求在另一个项目里。

## 2. 执行对应的命令

命令见 `/req` 中的"开发流水线命令"一节。

**查看进度**（"做到哪了""进展怎么样"）：执行"查看进度"命令。

**暂停**（"先停一下""别做了"）：先确认一次，说明停止后当前步骤做到一半的工作不会保留，已完成的步骤会保留。确认后执行"暂停"命令。暂停命令同时会取消预约的开始、提醒和自动继续；只想取消这些时也用它。

**继续**（"继续开发""接着做"）：执行"继续"命令。
- 如果上次停在"需要需求方决定"，或者 spec 在暂停期间改过，流水线会从方案设计开始，在已有方案和代码的基础上处理变化的部分，提前告诉用户这一点。
- 输出"未启动"时，按 `/req` 中的说明处理。

**研发完成，待测试验证**（分阶段执行，查看进度显示这个状态时）：告诉用户下一步是提测，转到 `verify.md` 手册。用户说"继续"时也按 `verify.md` 处理，不要直接执行继续命令。

**从头重来**：只有用户明确要求放弃之前的结果时才执行"从头重来"命令，执行前确认一次。

## 3. 转告结果

按 `{{REQ_KIT_ROOT}}/skills/result-report/SKILL.md` 用一两句话说明：现在在做什么、已经完成了哪些、进行了多久，有遗留问题或等待决定的事项时一并说明。输出中有"agent 最近在做"几行时（从 Paseo 实时读取），挑一两条用白话转述，例如"正在运行测试""刚修改了登录接口"，不要原样贴命令。

用户想看细节时，可以告诉他：
- 每个步骤都在这个对话的子 agent 列表里，点开可以看到它的工作过程。
- 功能目录下的 `progress.md` 按时间记录了每一步的结果。
- 出问题时，`.pipeline/pipeline.log` 是运行日志。
