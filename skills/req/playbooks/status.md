# 手册：查看进度、暂停、继续

## 步骤

1. 找到功能目录
2. 执行对应的命令
3. 转告结果

## 1. 找到功能目录

- 这个对话里已经谈过的需求：用它的功能目录。
- 否则看当前目录下的 `docs/features/*/.pipeline/state.json`：只有一个时用它；有多个时，列出它们（目录名和 `spec.md` 的标题），请用户选择。
- 一个也没有：告诉用户当前项目里没有找到开发中的需求，问他是不是想提一个新需求，或者需求在另一个项目里。

## 2. 执行对应的命令

命令见 `/req` 中的"开发流水线命令"一节。

**查看进度**（"做到哪了""进展怎么样"）：执行"查看进度"命令。

**暂停**（"先停一下""别做了"）：先确认一次，说明停止后当前步骤做到一半的工作不会保留，已完成的步骤会保留。确认后执行"暂停"命令。

**继续**（"继续开发""接着做"）：执行"继续"命令。
- 如果上次停在"需要需求方决定"，或者 spec 在暂停期间改过，流水线会从方案设计重新开始，提前告诉用户这一点。
- 输出"未启动"时，按 `/req` 中的说明处理。

**从头重来**：只有用户明确要求放弃之前的结果时才执行"从头重来"命令，执行前确认一次。

## 3. 转告结果

用一两句话说明：现在在做什么、已经完成了哪些、进行了多久，有遗留问题或等待决定的事项时一并说明。

用户想看细节时，可以告诉他：
- 每个步骤都在这个对话的子 agent 列表里，点开可以看到它的工作过程。
- 功能目录下的 `progress.md` 按时间记录了每一步的结果。
- 出问题时，`.pipeline/pipeline.log` 是运行日志。
