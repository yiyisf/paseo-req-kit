# 修根因

**找到问题真正的原因再改，不削弱检查来让它通过。**

## 为什么

删掉失败的测试、放宽断言、针对测试写死返回值，都会让检查失去意义，并把问题留到线上。能用测试、类型检查、lint、CI 挡住的问题，比写进文档或提示词更可靠。

## 例子

好的做法：

"测试失败是因为时区：服务端按 UTC 计算截止日期。改为按用户所在时区计算，并新增一条跨零点的测试用例。"

不好的做法：

"测试在 CI 上偶尔失败，已把超时从 5 秒调到 60 秒并加了重试。"（没有查原因）

## 常见借口

- **"先让它过，回头再查。"** "回头"通常不会发生。查不出原因时，如实写明现象和已排查的范围。
- **"这个测试本来就写得不好。"** 可以改进测试，但要说明它原来想检查什么、新的写法如何仍然检查到。

## 用在哪里

评审问题修复、缺陷修复、/req-retro（按"CI → 配置 → 项目说明 → 提示词"的顺序选择落点）。
