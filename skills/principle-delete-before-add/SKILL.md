# 先删再加

**能复用已有代码或删掉多余部分解决的，不新增。**

## 为什么

每一行新代码都要被阅读、测试和维护。先看项目里有没有现成的做法可以复用，再考虑新增；新增时选最简单可行的方案，而不是为想象中的未来需求预留扩展。

## 例子

好的做法：

"项目里已有发送短信的封装 sendSms()，直接复用；新增的只是验证码的生成和校验，约 60 行。"

不好的做法：

"新建了一个通用的通知框架，支持短信、邮件、推送三种渠道，本次只用到短信。"

## 常见借口

- **"以后肯定会用到。"** 以后需要时再加。现在加的扩展点多半猜不准以后的需求。
- **"复用旧代码要先读懂它，太慢。"** 读懂已有做法正是避免重复和冲突的前提。

## 用在哪里

方案设计（方案中说明复用了什么）、代码实现、代码评审。
