req-kit 是什么 ​

req-kit 是运行在 Paseo 上的一套需求开发体系。它帮助非专职开发、但有一定技术背景的同事——测试、产品经理、项目经理——把一个需求从"我想要……"推进到"可以验收"：

  • 你在 Paseo 的对话里输入 /req 和一句话，AI 用访谈的方式和你把需求谈清楚，写成一份需求说明（spec.md）请你确认。
  • 确认后，一组 AI agent 在后台依次完成方案设计、方案审核、代码实现、代码评审、服务启动、功能验证、缺陷修复和完成报告。
  • 进展、需要你决定的问题和最终结论都发回同一个对话；你再按验收标准逐条验收。

整个过程只在本地提交代码，合并和上线仍然由人决定。

为什么需要它 ​

直接让一个编码 agent "把这个需求做了"，常见的问题是：

问题req-kit 的做法
需求没谈清楚就开工，做出来不是想要的先访谈，一次一个问题，给选项和推荐；确认前另一个模型独立审阅需求说明
自己写、自己检查，问题被忽略做事的和检查的是不同的 agent，可以配置不同的模型；评审小组可以并行审核
说"做完了"，其实没验证验证由独立的 agent 按验收标准逐条进行，结论必须有证据；报告从严判定
过程不可见，出了问题无从查起每一步是一个挂在你对话下的子 agent，产物都是功能目录里的文件
一跑几个小时，中途断了要重来中断后从断点继续；需求变了只处理变化的部分；临时错误自动重试、自动继续

适合谁 ​

  • 测试同事：把测试中发现的小需求、改进自己推进；也可以作为"测试阶段"的接手人，按提测说明在测试环境中验证。
  • 产品经理：把需求讲清楚，拿到可以试用的结果和一份讲人话的报告。
  • 项目经理：用需求总览（req digest）看所有需求的状态，接入企业 IM 收通知。
  • 开发同事：负责安装、项目接入（/req-setup）和代码合并；也可以直接用它推进小需求。

它不做什么 ​

  • 不合并、不推送、不上线，不连接生产环境，不使用生产凭据。
  • 不替代代码审查：报告的附录写明了分支、提交和改动，由开发同事审阅后合并。
  • 不追求通用的编码提效，见 范围与取舍。

支持的环境 ​

项目要求
Paseo0.11（daemon 在运行；网页版或桌面版都可以）
Node.js22 或更新
系统macOS、Linux、Windows
agentClaude Code、Codex、OpenCode、Pi 中至少一种，已在 Paseo 中登录
