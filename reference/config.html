0005 不在默认分支上运行，只做本地提交

0008 入口 skill 之间不互相调用

0009 程序与本机配置分开存放，按版本目录并存

0010 需求总览现场生成，不维护 INDEX.md

0011 完成后修改 spec 可以继续开发

0012 评审小组：首轮并行评审，评审者核实汇总

0013 发布不使用 changesets 等工具

0014 外部通知只留接口，不内置任何 IM

0015 需求变更后增量继续，而不是从零重做

0016 一键升级：从 git 标签下载到 versions/ 再切换

0017 用好 Paseo 自身的能力：profile、工作区脚本、用量和时间线

0018 可选：流水线为需求新建 worktree 工作区

0019 用 Paseo 的并行子 agent：确认前独立审阅、方案提案

0020 调度：用 Paseo 定时任务把消息发回对话，排队在本机进行

0021 npm 分发：全局包是版本管理器，各版本仍装在 versions/ 下

0022 分阶段执行：研发阶段、闸口、测试验证阶段

0024 让分歧更早暴露：验收例子、方案确认点、两个方向的评审、反复的问题变成规则

0025 联合需求：一个需求同时改几个仓库

0026 本机的需求索引、使用记录和 req api

0027 Paseo 插件：随 req-kit 一起发布，只通过 req api 工作

0028 外部系统对接：命令写法在配置里，内容由 AI 整理，调用是确定的

0029 从卡片开始的需求：需求会话代替人，卡片描述代替对话

配置项 ​

配置分三层，后者覆盖前者：

  1. 本机配置 ~/.req-kit/config.json（REQ_KIT_HOME 可以改变目录）——req configure 生成；
  2. 团队配置：本机配置的 teamConfig 指向的文件，适合放进团队共用的仓库；
  3. 项目配置：仓库根目录的 .requirement-pipeline.json，只写和本机不同的部分。

daemonUrl、daemonPasswordEnv、teamConfig 只能写在本机配置中；notifiers、integrations、push、factory、people 不能写在项目配置中（会运行命令、推送或发消息）。在 Paseo 插件首页的"配置"中可以看到每一项现在的值和来自哪个文件。写错时，流水线启动前会说明哪一项、为什么。完整的示例见仓库的 config.example.json。

agent ​

json
{
  "agents": {
    "builder": { "paseoProfile": "实现" },
    "reviewer": { "provider": "codex/<模型 ID>", "modeId": "full-access" }
  }
}
字段说明
paseoProfilePaseo 中 agent profile 的名称；写在它旁边的字段优先
providerprovider/model，例如 claude/claude-sonnet-5、pi/anthropic/claude-sonnet-5
modeId必须是不会停下来请求批准的模式：Claude Code bypassPermissions、Codex full-access、OpenCode build（加 featureValues: { "auto_accept": true }）、Pi 不写
thinkingOptionId、featureValues、options原样传给 provider

流程 ​

配置默认说明
defaultProfilestandard需求说明没写档位时用的档位
profiles.<档位>.rounds快速 1/1/1，标准 2/3/3方案审核、代码评审、缺陷修复的最多轮数
profiles.<档位>.serviceStart快速 false，标准 true是否做服务启动验证
phases连续执行方式和测试阶段的选项，见 分阶段执行与提测
specReviewstandard确认前独立审阅需求说明：standard（标准档）、always、off
designProposals关闭{"enabled": true}：方案设计前由几个 agent 并行各提一份方案
reviewPanel关闭评审小组：首轮方案审核和代码评审由多位成员并行评审，再由 reviewer 核实汇总
stepTimeoutMinutes.<步骤>20–240 分钟每个步骤的总时限
resultFollowUps2结果文件缺失或不合格时提醒补写的次数
retry2 次，等 60/300 秒临时错误（限流、网络）后自动重做这一步
selfHealtrue1.12：超时时 agent 还在做就再等一轮；agent 报错、结果文件无效时新开 agent 重做一次
answerQuestionsFirsttrue1.12：方案审核要需求方决定的问题，先由 builder 从代码和文档中自答
agents.fallback无1.12：备用模型，报错重做、限流重试用完时换它做这一步

质量与范围 ​

通常写在项目配置 .requirement-pipeline.json 中，见 项目定制与运行规则。

配置默认说明
checks[]质量门：流水线自己运行的检查，[{ "name", "command", "cwd"?, "paths"?, "timeoutMinutes"? }]；只拦改动前通过、现在失败的检查
qualityGate.fixAttempts2新失败发回 agent 修复的次数，用完照常继续并写进报告
qualityGate.timeoutMinutes20单项检查的默认时限
slices标准档，最多 6 片按切片实现：profiles 哪些档位，max 最多几片
requirementTypes缺陷、重构、评估哪些需求类型按自己的做法运行；去掉的按新需求处理
relatedRepos[]只读参考的其他仓库，[{ "name", "path", "role"? }]，path 相对项目目录
designApproval界面改动，标准档方案确认点：mode（ui / always / off）、profiles、autoContinueHours（超时按方案继续，0 一直等）
reviewAxes开启，标准档第一轮代码评审由规格评审和规范评审并行，再汇总：enabled、profiles

Paseo 能力 ​

配置默认说明
attachToOriginChattrue步骤 agent 作为子 agent 挂在发起的对话下
archiveStepAgentsfalse步骤完成后归档它的 agent
paseoServicesauto用 paseo.json 中的服务（由 Paseo 启动、分配端口）；off 由步骤 agent 自己启动
serviceReadySeconds120等待服务就绪的时间
browserVerifyauto有 Paseo 浏览器工具时，验证步骤在浏览器中实际操作
quotaWarnPercent85开始时额度用到这个比例以上就提醒；0 关闭

通知与调度 ​

配置默认说明
notifyMilestonestrue关键节点（方案确定、开始验证、修复缺陷）在对话里说一句
notifiers[]外部通知模块（企业 IM 等），见 外部通知事件
people{}1.12：需求方姓名到 IM 账号的对应，按人通知时用；只能写在本机或团队配置中
push.mergeRequest无1.12：推送后用 glab 等命令建草稿合并请求，参数可用 {branch} {target} {title} {description}
autoConfirm.hours0（关闭）1.12：快速档、没有待答问题的卡片，过这么久没有异议就开始
waitingReminderHours24等待需求方回答、或研发完成待测试超过这么久，提醒一次；0 关闭
autoResumeMinutes / autoResumeMax30 / 2临时错误中断后自动继续的等待时间和次数；0 关闭
watchdogMinutes60运行期间定时检查，进程意外退出时自动继续；0 关闭（1.12 起默认 60）
maxConcurrentPipelines0本机同时运行的流水线上限，满了排队；0 不限
queuePollSeconds60排队时检查空位的间隔

本机与团队 ​

配置默认说明
daemonUrlws://127.0.0.1:6767/wsPaseo daemon 地址
daemonPasswordEnvPASEO_DAEMON_PASSWORD存放 daemon 密码的环境变量名
teamConfignull团队配置文件的路径
