设计决定（ADR）

总览

0001 步骤 agent 挂在发起的对话下

0002 对话过程中不切换工作目录

0003 第 3–11 步由脚本引擎驱动，不用 Hub 多步骤工作流

0004 步骤结论只看结果文件

0005 不在默认分支上运行，只做本地提交

0006 只安装到 ~/.agents/skills 和 ~/.claude/skills

0007 自带需求访谈 skill，不依赖外部 skill 包

0008 入口 skill 之间不互相调用

0009 程序与本机配置分开存放，按版本目录并存

0010 需求总览现场生成，不维护 INDEX.md

0011 完成后修改 spec 可以继续开发

0012 评审小组：首轮并行评审，评审者核实汇总

0013 发布不使用 changesets 等工具

0014 外部通知只留接口，不内置任何 IM

0015 需求变更后增量继续，而不是从零重做

0016 一键升级：从 git 标签下载到 versions/ 再切换

0017 用好 Paseo 自身的能力：profile、工作区脚本、用量和时间线

0018 可选：流水线为需求新建 worktree 工作区

0019 用 Paseo 的并行子 agent：确认前独立审阅、方案提案

0020 调度：用 Paseo 定时任务把消息发回对话，排队在本机进行

0021 npm 分发：全局包是版本管理器，各版本仍装在 versions/ 下

0022 分阶段执行：研发阶段、闸口、测试验证阶段

0023 需求类型、质量门、按切片实现

0024 让分歧更早暴露：验收例子、方案确认点、两个方向的评审、反复的问题变成规则

0025 联合需求：一个需求同时改几个仓库

0026 本机的需求索引、使用记录和 req api

0027 Paseo 插件：随 req-kit 一起发布，只通过 req api 工作

0028 外部系统对接：命令写法在配置里，内容由 AI 整理，调用是确定的

0029 从卡片开始的需求：需求会话代替人，卡片描述代替对话

0030 接单器：共享机器上定时接卡片、转达回复

0031 少等人：每种中断都有自动的下一步

state.json ​

流水线的运行状态，位于 docs/features/<目录>/.pipeline/state.json，只由引擎写入，不提交。

当前格式：version 1 ​

字段类型含义
versionnumber格式版本。没有这个字段的文件按 1 处理
repostring仓库目录（绝对路径）
featureDirstring功能目录（相对路径，/ 分隔）
statusrunning | waiting_for_business | failed | completed | phase_done | waiting_for_approval当前状态。waiting_for_business 表示等待需求方决定；phase_done（1.7.0 起）表示研发阶段已完成、停在闸口等待测试验证；waiting_for_approval（1.8.0 起）表示方案已通过审核、等待需求方确认 preview.md，--approve 继续。旧引擎把不认识的状态当作可以继续的中断：phase_done 继续时直接做验证，waiting_for_approval 继续时不经确认直接写代码
attemptnumber第几次从方案设计开始
specHashstring启动时 spec.md 的 sha256
originAgentIdstring | null发起对话的 agent，通知发往这里
pidnumber流水线进程
startedAt / updatedAtISO 时间
resultsobject已完成步骤的结果，键为步骤键（如 code_review-r2）
historyarray每次步骤执行的记录：agent、起止时间、结果、错误；usage（可选，1.3.0 起）为 agent 报告的用量：inputTokens、cachedInputTokens、outputTokens、totalCostUsd，agent 没有报告时为 null 或缺少；leftRunning（可选，1.11 起）为 true 表示失败时 agent 可能还在运行，下一次运行这一步时先看它；reattached（可选，1.11 起）为接着等上一次 agent 的次数
stopReason / outcomestring | null停止原因；最终结论
stopKindstring | null可选，1.12 起。停下等人的原因代码：必要的决定 approval（确认方案）、phase_gate（研发完成，等待测试）、business（需求方决定）、reproduce（缺陷复现不了）；中断 timeout、agent_error、invalid_result、transient、stopped、process_exit、other。运行中或完成时为 null
recoveriesarray可选，1.12 起。流水线自己处理掉的问题（最多保留 200 条）：at、key（步骤键）、kind（retry 重试 / reattach 接着等上一次的 agent / reuse_result 沿用上一次 agent 的结果 / extend_timeout 超时后多等一轮 / redo 新开 agent 重做 / fallback 换备用模型 / auto_resume 预约自动继续 / quota_wait 预约在额度恢复后继续 / self_answer 方案审核的问题由 builder 自答）、detail
profilequick | standard档位
branchstring | null工作分支，启动时确定
milestonesstring[]已发送的进展通知，续跑时不重复发送
incrementalobject | null可选，1.3.0 起。需求变更或回答问题后的继续：fromAttempt（接着哪一次）、reason、baseCommit（本次开始时的提交，评审看这之后的改动）、hadImplementation（上一次是否已写过代码）。第一次运行和 --restart 为 null
worktreeobject | null可选，1.5.0 起。用 --worktree 启动、在为需求新建的工作区中开发时：workspaceId（Paseo 工作区）、sourceRepo（对话所在的目录）。此时 repo 是新工作区的目录
schedulesarray可选，1.6.0 起。这次运行创建的 Paseo 定时任务：id、kind（reminder 提醒 / auto-resume 自动继续 / watchdog 定时检查）、at。下一次运行或暂停命令会取消它们
autoResumesobject | null可选，1.6.0 起。attempt、count：这次尝试已经预约过几次自动继续
queuedSincestring | null可选，1.6.0 起。正在排队（maxConcurrentPipelines）时为开始排队的时间
phasesobject | null可选，1.7.0 起。这次运行的执行方式：mode（continuous / gated / develop-only）、environment（local / deployed）、defects（fix / handback / report）。没有时按 continuous、local、fix 处理
phasedevelop | verify可选，1.7.0 起。当前阶段。用字符串而不是编号，以后增加阶段不用改格式
verifyAtstring | null可选，1.7.0 起。--verify-at：研发完成后在这个时间开始测试验证
handbacksnumber可选，1.7.0 起。测试验证把缺陷退回研发阶段的次数（defects 为 handback），上限为档位的 defectFix 轮数
typedefect | refactor | assessment | null可选，1.8.0 起。spec 中"类型"对应的做法；新需求、小改动和配置关掉的类型为 null
codeBaseobject | null可选，1.8.0 起。attempt、commit：这次尝试在改动任何代码之前的提交，质量门的基线和范围检查从这里比较。尝试开始时就已经写过代码的旧记录为 commit: null
jointarray | null可选，1.8.0 起。联合需求（spec 的 - 联合开发：）中其他仓库的工作区：name（relatedRepos 中的名称）、slug（步骤键的后缀，如 implement@backend）、sourceRepo（切出工作区的那份检出）、repo（工作区目录）、workspaceId、branch、specHash（最近一次同步过去的 spec），以及这个仓库自己的 codeBase 和 gate（格式同顶层）。见 ADR 0025
approvalobject | null可选，1.8.0 起。方案确认点：attempt（哪一次尝试的方案）、status（waiting / approved）、at。需求变更后的新尝试需要重新确认
externalobject | null可选，1.9.0 起。外部系统中的卡片，按集成名称：id（卡片编号）、url、status（最近设置的状态）、syncedAt、pending（没有成功、等待补发的调用：action 为 create / status、event、status、at、attempts、error）。见 ADR 0028
pushedarray | null可选，1.10 起。从卡片开始、配置了 push 的需求推送过的分支，每个仓库一条（主仓库在前）：repo、remote、branch、at、error（成功时为 null）。见 ADR 0029
gateobject | null可选，1.8.0 起。质量门：baseline（attempt、commit、at、results：每项检查改动前 pass / fail），runs（每次运行：key 步骤键、attempt、at、checks（name、result：pass / fail / skipped、failedBefore）、newFailures、fixRounds、passed）。各次运行的完整输出在 .pipeline/checks/<步骤键>/

schedules[].kind 在 1.7.0 起还可能是 verify-start（--verify-at 预约的测试验证开始），1.8.0 起还可能是 approval-continue（方案确认超时后按方案继续，designApproval.autoContinueHours）。history 中每条步骤记录在 1.7.0 起有可选的 phase（develop / verify），用于按阶段统计用时与用量；没有时按研发阶段统计。

迁移 ​

只增加可选字段（缺少时按默认值处理，旧版本引擎读到也不出错）时不提升版本，以便回滚到旧版本后仍能继续已有的流水线；在上表中注明"可选"和起始版本即可。

引擎（engine/src/state.ts）中 STATE_VERSION 是当前版本，STATE_MIGRATIONS[n] 把第 n 版升级到第 n+1 版。增加必需字段或改变已有字段的含义时：

  1. STATE_VERSION 加 1。
  2. 在 STATE_MIGRATIONS 中加一个从旧版本到新版本的函数，为旧文件补上默认值。
  3. 在 engine/test/state.test.ts 中加一条迁移测试，更新本文件。
