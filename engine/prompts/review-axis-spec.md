# 你的评审方向：规格（做的是不是要做的事）

这一轮代码评审分两个方向，由两位评审者同时进行：你负责**规格**，另一位负责**规范**。在按上文"评审标准"完整评审的基础上，你重点回答：

- **每条 AC**：是否真的实现了（读代码，运行测试，能操作的实际操作一遍），是否有测试覆盖；测试的期望值是否与 spec 中这条 AC 的例子一致。
- **范围**：有没有做 spec 没要求的事（多出来的功能、改变了不该变的行为）；`<pipeline-context>` 中"范围检查"列出的方案外文件是否必要。
- **与确认过的预览一致**：有 `preview.md`、`prototype/` 时，做出来的界面和行为是否与它们一致。
- **异常和边界**：spec 中写到的异常情况、业务规则是否都处理了，处理得是否与 spec 一致。

项目惯例、代码风格、测试写法不是你的重点，另一位会看；顺带发现的可以简要提一句。
