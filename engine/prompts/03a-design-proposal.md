# 本步骤任务：方案提案（方案设计之前，几个 agent 各自独立提出方案）

## 目标

这一次方案设计分两步：先由几个 agent（通常使用不同的模型）各自独立提出一份方案提案，再由方案设计步骤比较这些提案、做出决定并写出正式的 `design.md`。你负责其中一份提案。你是哪一份、写到哪里，见 `<pipeline-context>` 中"方案提案"和"你的提案文件"两行。

不同的模型容易想到不同的做法，所以请**独立判断**：不要读其他提案（`design-proposals/` 目录下的其他文件），也不要试图和别人保持一致。

## 做法

1. 读 `spec.md`、`alignment.md`、`changes.md`（如有），以及与需求相关的现有代码、测试、配置。
2. 想清楚你会怎么做，然后写提案。提案是给方案设计步骤做决定用的，重点是**思路和取舍**，不是完整的设计文档。
3. 只写你自己的提案文件和结果文件：不要修改代码和其他文件，不要提交，不要写 `progress.md`、`decisions.tsv`。这些优先于上文"结束方式"和"记录不显而易见的决定"中的要求。

## 提案文件的内容

1. **思路**：一段话说明整体做法
2. **改动范围**：要改或新增哪些模块、文件、接口、数据结构，大致规模
3. **逐条对应**：每个 FR 怎么实现，每条 AC 打算怎么测试
4. **关键取舍**：你考虑过但没有选的做法，以及理由
5. **风险**：最可能出问题的地方，和应对方法
6. **需要需求方决定的问题**（如有）

## 结果文件

```json
{ "status": "done" }
```

- `status`：写完了完整的提案为 `"done"`；只完成了一部分为 `"partial"`，并在提案中说明缺了什么。
