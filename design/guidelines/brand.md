# req-kit 品牌手册

req-kit 的所有界面都用这一套设计语言：审查原型、验收清单、代码审查三个网页，Paseo 插件，文档站和首页，汇报幻灯片、海报和社媒图。它和 CMASTER（编排平台与 Workflow IDE）同属 **Bento Launchpad** 家族，同一片深海军蓝夜空、同样的便当格卡片、等宽小标题和三色极光；不同的是主色。CMASTER 用橙色，req-kit 用**青柠绿**（`brand-500`）。

## 气质

CMASTER 像深夜里的发射台控制面板；req-kit 是发射前的那张**放行检查单**。

- **同一片夜空。** 中性色、数据色、AI 色、状态色、字体、间距、圆角、阴影都和 CMASTER 取同样的值。两个产品放在一起，看得出是一个团队做的。
- **一步一格。** 需求从对齐到验收是一串步骤，每一步装进一张卡片：一份需求说明、一个方案、一条评审意见、一项验收标准。
- **放行灯只亮在人做决定的地方。** 确认方案、评审通过、开始开发、提交验收：这些按钮是青柠绿的。AI 做完的事用靛色标出，流水线正在跑的用青色，人要拍板的用青柠绿，三者一眼分得开。
- **技术感来自真实细节。** 功能目录、分支名、提交号、命令、token 数都用等宽字体如实写出来，不加装饰性的科幻元素。

## 三种光，三种含义（req-kit 里）

| 颜色 | token | 在 req-kit 里表示 | 例子 |
|---|---|---|---|
| 青柠绿 | `brand-500` / `brand-text` / `brand-tint` | 该你做决定、可以操作、当前选中 | "确认方案""评审通过""开始开发"按钮；原型上点选的区域和编号图钉；当前标签 |
| 靛色 | `ai` / `ai-tint` | AI 写的或 AI 下的结论 | AI 评审意见卡；agent 步骤；Sparkles 图标；"AI 已验证" |
| 青色 | `data` / `data-tint` | 数据和正在运行 | 流水线进行中的步骤；命令、文件路径；token 用量 |

不要混用。青柠绿不表示"通过"（那是 `status-success`），也不表示警告（那是 `status-warning`）。

## 标志性元素

1. **极光背景**：页面顶部三层径向光晕叠在 `canvas` 上，中上方 `aurora-brand`（青柠），右上 `aurora-data`，左中 `aurora-ai`。只用于首页、文档首页、幻灯片封面、海报；审查页、插件和文档正文页不用。
2. **Bento 卡片**：`surface-2` 底、1px `border-default`、`radius-xl`（大卡）或 `radius-lg`（小卡）、`shadow-card`。悬停描边变 `border-strong`；选中用 `brand-500` 描边加 `glow-select`。
3. **等宽小标题（eyebrow）**：`eyebrow` 样式，大写英文，`brand-text` 色，放在区块或卡片标题上方，例如 `SPEC`、`CODE REVIEW`、`ACCEPTANCE`。
4. **渐变关键词标题**：`display-xl` / `display`，关键词用 `brand-300` → `brand-500` 的青柠渐变，整个关键词都亮（CMASTER 从白色起渐变；青柠本身很亮，从白色起会让第一个字看不出被强调）。浅色主题用 `brand-text` 纯色。一个标题最多一处渐变。
5. **代码胶囊**：功能目录、分支、命令、配置项用 `code-sm` 胶囊，例如 `feature/20261024-export`。
6. **步骤轨**（req-kit 独有）：一条细线串起的编号圆点，表示需求走到了哪一步。已完成的圆点打勾，当前步是青色进行中或青柠绿"等你处理"，未到的是空心。用在插件需求详情、首页的流程介绍、幻灯片。

## 设计原则

1. **人做决定的地方最显眼。** 每个页面只有一个青柠绿主按钮，它就是"这一页要你做的那件事"。
2. **AI 的结论和人的决定分开显示。** AI 写的东西有靛色标记和"AI"字样；人写的意见、人的结论没有这个标记。代码审查页上，AI 意见和评审人意见分两种卡片。
3. **状态一眼可读。** 颜色 + 图标 + 中文词，缺一不可（进行中 / 已完成 / 等你处理 / 没通过 / 已跳过 / 没验证）。
4. **说人话。** 读者是测试、产品、项目经理，不一定会写代码：写"这一步在做什么、你要做什么"，代码和命令放在可以展开的地方。
5. **真实胜过修饰。** 截图、数字、例子用真实的或可核实的；没做出来的能力不展示。
6. **证据跟着结论。** 写"通过"的地方能点开看到依据：运行了什么、看到了什么。

## 文案

- **中文优先，动词开头，说清楚会发生什么。** "确认方案""退回修改""评审通过""把它跑起来试用"；不写"确定""提交""OK"。
- **标题写结果，副标题写怎么做到。** 例："一句需求，到可验收的功能" + "用对话谈清楚，由 agent 在后台完成方案、实现、评审和验证。"
- **称呼用"你"。** 出错时写"发生了什么 + 怎么办"。
- **中英文与数字之间加空格。** 技术标识一律用代码胶囊。
- **不用 emoji。** 图标统一用 Lucide。
- **统一术语：**

| 用这个词 | 指 | 不要写 |
|---|---|---|
| 需求 | 一个要做的功能或修改，对应一个功能目录 | 工单、任务 |
| 需求说明 | `spec.md` | 规格书、PRD |
| 对齐 | 在对话里把需求谈清楚 | 访谈、澄清会 |
| 方案 | 方案设计步骤写的 `design.md` 和原型 | 设计稿 |
| 流水线 | 后台依次运行的一组步骤 | 工作流、pipeline（开发者文档可并用） |
| 步骤 | 流水线里的一环，由一个 agent 完成 | 阶段、节点 |
| 质量门 | 流水线自己运行的 lint、测试、构建 | 门禁 |
| 代码审查 | 人在插件里看改动、写意见 | CR、code review |
| AI 评审 | 代码评审步骤里 agent 给的意见 | 机审 |
| 验收 | 需求方按验收标准核对 | UAT |
| 等你处理 | 需要人来做的事的列表 | 待办、通知 |
| 退回修改 | 评审人或验收人要求改 | 打回、驳回 |

## 色彩

- **层级**：`canvas`（页面）→ `surface-0`（顶栏、外壳）→ `surface-1`（侧栏、面板）→ `surface-2`（卡片）→ `surface-3`（输入框、胶囊、悬停）。
- **文字**：`text-primary` 标题与正文，`text-secondary` 导语与描述，`text-muted` 提示与脚注；在所有 surface 上满足 4.5:1。
- **品牌**：主按钮 `brand-500` 底 + `on-brand` 字 + 1px `brand-edge` 描边（浅色主题靠它和白底分开）；悬停 `brand-400`，按下 `brand-600`；青柠绿的文字和细线用 `brand-text`；选中底色 `brand-tint`；首页和海报的主行动加 `glow-brand`。**青柠底上的字永远是深色 `on-brand`，不用白字。**
- **AI 与数据**：`ai` / `ai-tint`、`data` / `data-tint`，只做小面积标记。
- **状态**：`status-*` + 对应 `*-tint`。代码改动用 `diff-added` / `diff-removed`（与成功、失败同色）。
- **不要**：大面积渐变底、紫蓝渐变按钮、彩色左边框卡片、把状态色当装饰、把青柠绿当"通过"。

## 字体

- **Geist**（拉丁）+ 苹方 / Noto Sans SC / 微软雅黑（中文）作为 `sans`；**Geist Mono** 作为 `mono`。网页从 Google Fonts 加载；内网打不开时自动退回系统字体（苹方、微软雅黑、Consolas），版式不变。
- 首页、幻灯片、海报：`display-xl`、`display`、`metric`。产品与文档：`title-lg` / `title-md` / `title-sm`、`prose`、`body`、`body-sm`、`caption`。等宽：`eyebrow`、`code`、`code-sm`。
- **字标 req-kit**：`sans` 800，字距 -0.02em，全小写；中间的连字符用 `brand-edge`（深色背景上就是青柠绿，浅色背景上是深一档的青柠，保证 3:1），其余用 `text-primary`。
- 正文行宽不超过 68 个汉字；数字列开启 `tabular-nums`。

## 间距与布局

- 4px 网格。控件内 `space-2`，列表行 `space-3`，面板 `space-4`，卡片内边距 `space-6`，卡片间距 `space-4`。
- 首页区块之间 `space-24`，区块标题与内容之间 `space-8`；内容最宽 1120px。
- 审查类网页：顶栏 48px，内容最宽 1200px，底部固定"决定栏"（见 `review-pages.md`）。

## 圆角与阴影

- 徽章、胶囊 `radius-sm`；按钮、输入 `radius-md`；小卡、意见卡、代码块 `radius-lg`；大卡、对话框、截图 `radius-xl`；版本胶囊、步骤圆点 `radius-pill`。
- 卡片 `shadow-card`，浮层和决定栏 `shadow-float`，对话框和宣传截图 `shadow-dialog`。侧栏只用描边。

## 动效

- 120ms 微交互，200ms 面板与浮层。缓动 `cubic-bezier(.2,.8,.2,1)`。
- 进行中的步骤 1.6s 脉动（`glow-run`）；首页区块进入时上移 12px 淡入一次；极光可以极慢漂移。不做视差和粒子。
- 尊重 `prefers-reduced-motion`。

## 图标

- **Lucide**，线宽 1.75；按钮和工具栏 16px，卡片标题前 18px，空状态 24px。
- req-kit 映射：需求说明 `FileText`，对齐 `MessagesSquare`，方案与原型 `PenTool`，流水线 `Workflow`，质量门 `ShieldCheck`，AI 评审 `Sparkles`（`ai` 色），代码审查 `GitPullRequest`，验收 `ClipboardCheck`，试用 `Play`，等你处理 `Inbox`，退回修改 `Undo2`，进行中 `LoaderCircle`，已完成 `CircleCheck`，没通过 `CircleX`，没验证 `CircleDashed`，危险命令 `OctagonAlert`，统计 `ChartColumn`。
- 只有图标的按钮必须有 `title` 和 `aria-label`。

## 标志

- **标志**：一条对勾形的流水线，前两个空心节点是"需求"和"开发"，终点是一盏实心的放行灯，外面一圈淡光。深色背景用 `reqkit-mark-dark.svg`（青柠），浅色用 `reqkit-mark-light.svg`（深一档的青柠 `brand-edge`，白底上 3:1），应用图标与 favicon 用 `reqkit-app-icon.svg`。
- 最小 16px，周围留白不少于标志高度一半；不改色、不描边、不加阴影。
- 和 CMASTER 并排出现时（例如团队介绍页），两个标志等高，中间留出一个标志宽度。

## 无障碍

- 焦点环：2px 实线 `focus-ring`，偏移 2px。
- 文本 4.5:1，图标与控件边框 3:1，深浅主题都要满足。青柠按钮在浅色主题靠 `brand-edge` 描边达到 3:1。
- 所有页面在 400px 宽度下可用，正文不横向滚动；只有代码差异和表格在自己的容器里横向滚动。
