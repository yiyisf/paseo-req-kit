# 环境准备：在一台新机器上从零开始

本文面向第一次在一台机器上准备 req-kit 环境的人：从安装 Node.js 和 Paseo 开始，到 `/req` 能在对话中使用为止。已经有 Paseo 在运行、只想装 req-kit 的，直接看 [安装与升级](安装与升级.md)。

整个过程大约 30 分钟，大部分时间花在下载上。

## 1. 各部分的关系

```text
你（Paseo 桌面端 / 网页 / 手机）
        │  对话
        ▼
Paseo daemon（本机后台服务，默认 ws://127.0.0.1:6767/ws）
        │  启动并管理
        ├── 聊天 agent（Claude Code、Codex、OpenCode、Pi……）：读取 /req 等 skill，和你对齐需求
        │        │  确认后启动
        │        ▼
        │   req-kit 流水线（Node.js 进程）──连接 daemon──▶ 步骤 agent（方案、实现、评审、验证……）
        └── 工作区、worktree、服务、定时任务
```

由此得出三条规则：

- **req-kit 装在运行 daemon 的那台机器上。** 你在笔记本上用桌面端连接一台远程开发机的 daemon 时，req-kit、Node.js、agent 都装在开发机上，笔记本上不用装。
- **流水线是由聊天 agent 启动的进程**，继承 daemon 和聊天 agent 的环境变量。daemon 密码之类的变量必须在 daemon 启动之前设置好（见第 6 节）。
- **流水线通过本机网络连接 daemon。** 聊天 agent 不能运行在禁止网络的沙箱中（例如 Codex 要用 `full-access` 模式）。

## 2. 清单

按顺序完成，每一步都有确认方法：

| # | 步骤 | 确认 |
| --- | --- | --- |
| 1 | 安装 Node.js 22+、git | `node -v` 显示 v22 或更高；`git --version` |
| 2 | 安装并启动 Paseo 0.11 | 桌面端能打开；或 `paseo daemon status` 显示在运行 |
| 3 | 安装至少一种 agent 并登录 | 在 Paseo 中用它开一个对话，能正常回复 |
| 4 | 安装 req-kit | `req doctor --no-project` 全部 ✓ |
| 5 | 冒烟测试 | [安装与升级](安装与升级.md) 第 5 节的四项 |
| 6 | 接入第一个项目 | 在项目对话中运行 `/req-setup` |

## 3. Node.js 和 git

req-kit 需要 **Node.js 22 或更新**（自带 npm）。git 用于工作区和本地提交，基本都需要。

| 系统 | 推荐安装方式 |
| --- | --- |
| macOS | 从 nodejs.org 下载 LTS 安装包，或 `brew install node@22`；git：`xcode-select --install` 或 `brew install git` |
| Windows | 从 nodejs.org 下载 LTS 安装包（勾选加入 PATH），或 `winget install OpenJS.NodeJS.LTS`；git：`winget install Git.Git` |
| Linux | 用 nvm 或 NodeSource 安装 Node.js 22（发行版自带的 Node.js 往往太旧）；git：系统包管理器 |

安装后**新开一个终端**再确认 `node -v`。公司网络需要镜像时，先配置好 npm（见第 8 节）。

## 4. 安装并启动 Paseo

req-kit 当前支持 **Paseo 0.11.x**（`package.json` 的 `reqKit.paseo`）。Paseo 升级到新的小版本（例如 0.12）之后，需要等 req-kit 发布支持它的版本，`req upgrade` 会自动选择匹配的版本。

### 方式一：桌面端（个人电脑推荐）

从 Paseo 官网（paseo.sh）的下载页或 GitHub Releases（getpaseo/paseo）下载对应系统的安装包。桌面端**自带 daemon 并自动启动**，不需要另外安装或启动。流水线要运行几个小时，期间不要让电脑休眠；被中断的流水线之后可以在对话中说"继续开发"续跑。

装好后：

1. 打开桌面端，确认能看到本机（Local）。
2. 设置 → 本机 → Agents：确认你要用的 agent 显示为可用；打开 **Enable Paseo tools** 和浏览器工具（可选，见 [安装与升级](安装与升级.md) 第 2 节）。
3. 推荐：在 Agent profiles 中建好"实现""评审"两个 profile（见 [安装与升级](安装与升级.md) 第 4 节）。

### 方式二：命令行（开发机、服务器、无图形界面）

```bash
npm install -g @getpaseo/cli@0.11   # 安装与 req-kit 匹配的 0.11.x
paseo                               # 首次设置：启动 daemon，询问是否开启加密中继（用于手机、远程配对）
```

常用命令：

| 命令 | 作用 |
| --- | --- |
| `paseo daemon status` | 查看 daemon 是否在运行、地址 |
| `paseo daemon start` / `stop` / `restart` | 启动 / 停止 / 重启 |
| `paseo daemon set-password` | 设置 daemon 密码（以哈希保存在 Paseo 的配置中） |
| `paseo provider ls` | 列出 daemon 能用的 agent 及其状态 |
| `paseo provider models <agent>` | 列出某个 agent 的模型 ID |
| `paseo onboard --port <端口>` | 首次设置时换端口（默认 6767） |

- Paseo 的数据目录默认是 `~/.paseo`，可以用环境变量 `PASEO_HOME` 或 `--home` 改。
- daemon 不在 6767 端口、或不在本机时，在 `~/.req-kit/config.json` 中改 `daemonUrl`（如 `ws://127.0.0.1:7000/ws`）。
- 需要开机或登录后自动运行时，用系统自己的方式（Linux 的 systemd 用户服务、macOS 的 launchd、Windows 的任务计划程序）在登录时执行 `paseo daemon start`。
- 也有官方 Docker 镜像，但它不带 agent，需要自己把 agent 装进镜像，而且 req-kit 要装在容器里。没有特别理由时，不建议在 Docker 中运行。

然后用桌面端、网页或手机连接这个 daemon 进行对话。

### 确认 daemon 正常

- 桌面端：能新建一个对话并得到回复。
- 命令行：`paseo daemon status` 显示在运行；`paseo provider ls` 至少有一个 agent 可用。

## 5. 底层 agent（只作提示）

Paseo 本身不包含 AI 模型，它驱动你已经安装的 agent 命令行工具。至少需要一种：**Claude Code**、**Codex**、**OpenCode** 或 **Pi**。

- 按各自官方文档安装，**在终端中运行一次并完成登录**（或配置好 API Key），确认能在终端中正常对话。
- 安装后**重启 Paseo**，让它重新查找本机的 agent；在 设置 → 本机 → Agents 中（或 `paseo provider ls`）确认显示为可用。找不到时用 `paseo provider diagnostic <agent>` 查看原因，常见的是命令不在 PATH 中。
- 公司网络访问模型服务需要代理时，代理要对 daemon 启动的 agent 生效（在启动 Paseo 的环境中设置 `HTTPS_PROXY`）。
- `builder` 和 `reviewer` 可以用同一个 agent，也可以不同。用不同厂商的模型做评审，往往能发现更多问题。
- 流水线中的 agent 以免确认模式运行，各 agent 的配置见 [安装与升级](安装与升级.md) 第 4 节。

## 6. daemon 密码（设了密码时）

只在本机使用、daemon 只监听 `127.0.0.1` 时，一般不需要密码。daemon 设了密码（`paseo daemon set-password`）时，req-kit 也要知道这个密码：

1. 把密码放进环境变量 `PASEO_DAEMON_PASSWORD`（变量名可以用配置中的 `daemonPasswordEnv` 改）。req-kit 不在文件中保存密码。
2. **这个变量必须在启动 Paseo 之前就存在**，这样 daemon 启动的聊天 agent 和流水线才能读到。设置后完全退出并重新打开 Paseo（命令行方式用 `paseo daemon restart`）。
3. 在 Paseo 对话中运行 `/req-doctor` 确认能连上 daemon。终端中的 `req doctor` 能连上、对话中的连不上，说明 Paseo 不是在设置了这个变量的环境中启动的。

`paseo` 命令行自己使用的是另一个变量 `PASEO_PASSWORD`，两者互不影响。设置方法见下一节表格中的"环境变量"一行。

## 7. 不同操作系统的差异

req-kit 在 macOS、Linux、Windows 上的功能相同，配置文件（`~/.req-kit/config.json`、项目中的 `.requirement-pipeline.json`）的写法也完全一样。差异集中在以下几处：

| 项目 | macOS | Linux | Windows |
| --- | --- | --- | --- |
| `~` 指的是 | `/Users/<用户名>` | `/home/<用户名>` | `%USERPROFILE%`（如 `C:\Users\<用户名>`） |
| 本机配置 | `~/.req-kit/config.json` | 同左 | `%USERPROFILE%\.req-kit\config.json` |
| 配置中写路径 | `/Users/me/team-config/req-kit.json` | 同左 | 用 `/` 或双反斜杠：`"C:/team-config/req-kit.json"` 或 `"C:\\team-config\\req-kit.json"`（JSON 中单个 `\` 是错误的） |
| 默认终端 | zsh（`~/.zshrc`） | 通常 bash（`~/.bashrc`） | PowerShell |
| `req` 命令（npm 安装） | npm 自动放进 PATH | 同左；全局安装报 `EACCES` 见下文 | npm 自动放进 PATH；PowerShell 报"禁止运行脚本"见下文 |
| `req` 命令（git 安装） | 把 `~/.req-kit/bin` 加入 PATH：`echo 'export PATH="$HOME/.req-kit/bin:$PATH"' >> ~/.zshrc` | 同左，写入 `~/.bashrc` | 安装器输出中给出的 PowerShell 命令（写入用户级 Path）；完整路径为 `%USERPROFILE%\.req-kit\bin\req.cmd` |
| 环境变量（如 daemon 密码） | 写入 `~/.zshrc`：`export PASEO_DAEMON_PASSWORD=…`。**从程序坞打开的桌面端读不到 shell 配置中的变量**，需要另外执行 `launchctl setenv PASEO_DAEMON_PASSWORD …`（重启电脑后失效），或从终端启动 Paseo | 写入 `~/.bashrc`；用 systemd 运行 daemon 时写在服务的 `Environment=` 中 | `[Environment]::SetEnvironmentVariable("PASEO_DAEMON_PASSWORD", "…", "User")`，然后完全退出并重新打开 Paseo 和终端 |
| `paseo.json` 中的命令 | bash 写法：`$PASEO_PORT` | 同左 | 准备命令（`worktree.setup`）用 PowerShell，脚本和服务用 cmd.exe：`%PASEO_PORT%`。见 [项目定制与运行规则](项目定制与运行规则.md) 的 paseo.json 一节 |
| 文件名大小写 | 默认不区分 | 区分 | 不区分 |
| 换行符 | LF | LF | git 可能把 LF 转成 CRLF；团队仓库建议在 `.gitattributes` 中约定，避免步骤 agent 的改动出现整文件差异 |

团队里不同系统混用时：

- 配置文件可以共用（团队配置、项目配置都不含系统相关的内容），路径统一用 `/`。
- `paseo.json` 中的命令只用 `npm ci`、`node scripts/xxx.mjs` 这类各系统一样的写法，端口由程序读取环境变量 `PASEO_PORT`。`/req-setup` 会问清系统并按此生成。
- `verify.md`（验证方法）中的命令同样写成各系统通用的形式，或分别写出两种写法。

### 各系统的常见问题

**Windows**

- **PowerShell 中输入 `req` 报"无法加载文件 …req.ps1，因为在此系统上禁止运行脚本"**：npm 生成的 `.ps1` 启动脚本被执行策略拦下。执行一次 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`；或者改用 `req.cmd`（在 PowerShell 中输入 `req.cmd doctor`），或者在 cmd 中使用。
- **路径过长**（`Filename too long`）：worktree 嵌套较深加上 `node_modules` 时可能超过 260 个字符。执行 `git config --global core.longpaths true`；必要时在系统中开启长路径支持（需要管理员）。
- 安装器不使用符号链接，不需要管理员权限，也不需要开发者模式。
- 杀毒软件实时扫描会明显拖慢 `npm install` 和测试，可以把项目目录和 `~/tools/req-kit` 加入排除列表（按公司规定）。

**macOS**

- 桌面端第一次打开时如果提示"无法验证开发者"，在 系统设置 → 隐私与安全性 中点"仍要打开"。
- 桌面端从程序坞启动时，环境变量和 PATH 与终端中不同。agent 在终端中能用、在 Paseo 中显示不可用时，先重启 Paseo；仍不行时用 `paseo provider diagnostic <agent>` 查看它在哪里找命令。

**Linux**

- **`npm i -g` 报 `EACCES`**：用系统包安装的 Node.js 全局目录需要 root 权限。不要用 `sudo npm i -g`（之后的 `req upgrade` 也会需要 root）；改用 nvm 安装 Node.js，或者 `npm config set prefix ~/.npm-global` 并把 `~/.npm-global/bin` 加入 PATH。
- 没有图形界面时用命令行方式运行 daemon（第 4 节方式二），用另一台电脑上的桌面端或手机连接。内置浏览器验证需要有一个在线的桌面端，没有时流水线会改用其他验证方式。

## 8. 公司网络

| 需要访问 | 用途 | 访问不了时 |
| --- | --- | --- |
| npm 源 | 安装 Paseo 命令行、req-kit 及依赖、升级 | 配置公司镜像：`npm config set registry <镜像地址>`（或团队的 `.npmrc`）；离线安装见 [安装与升级](安装与升级.md) 第 3 节 |
| GitHub | git 方式安装和升级、下载 Release 安装包 | 改用 npm 方式；或用 `--from <内网镜像地址>` / 环境变量 `REQ_KIT_REPO_URL` |
| 模型服务 | agent 调用模型 | 在启动 Paseo 的环境中设置 `HTTPS_PROXY`，并按各 agent 的文档配置 |
| `127.0.0.1:6767` | 流水线连接 daemon | 本机地址，一般不受影响；本机代理软件要把 `127.0.0.1`、`localhost` 排除在外（`NO_PROXY`） |

设置了 `HTTPS_PROXY` 时，建议同时设置 `NO_PROXY=127.0.0.1,localhost,.localhost`，避免本机连接和服务代理地址（`*.localhost:6767`）被转给代理。

## 9. 一台 daemon，多人使用

- 一台开发机上的 daemon 可以被多人连接使用，req-kit 只需在这台机器上装一次，本机配置（`~/.req-kit/config.json`）属于运行 daemon 的那个系统用户，所有人共用。
- 想要每人有自己的模型或通知设置时，各自运行自己的 daemon（各自的系统用户），各装一份 req-kit。
- 步骤 agent 以免确认模式运行，可以执行任何命令。不要在放有生产凭据的机器上运行 daemon，最好用专门的开发机或虚拟机。

## 10. 排错速查

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| `req` 不是命令 / command not found | 刚装完没开新终端；git 方式安装没加 PATH | 新开终端；或按第 7 节加入 PATH；或用完整路径 |
| `req configure`、`req doctor` 连不上 daemon | Paseo 没有运行；端口改过；设了密码 | 打开桌面端或 `paseo daemon start`；改 `daemonUrl`；按第 6 节设置密码变量 |
| 配置向导中没有任何 agent | agent 未安装、未登录，或 Paseo 找不到它 | 第 5 节：终端中先登录，重启 Paseo，`paseo provider ls` |
| 对话中输入 `/req` 没有反应 | 对话是在安装 req-kit 之前打开的；agent 读取 skill 的位置不同 | 新开一个对话；Pi 用 `/skill:req`；Codex 直接说"用 req 帮我……" |
| 流水线启动后马上失败，提示连接被拒绝或网络错误 | 聊天 agent 运行在禁止网络的沙箱中 | Codex 用 `full-access` 模式；见 [项目定制与运行规则](项目定制与运行规则.md) 的注意事项 |
| 设了密码：终端中 `req doctor` 正常，对话中 `/req-doctor` 连不上 daemon | Paseo 不是在设置了变量的环境中启动的 | 第 6 节第 2 步，macOS 见第 7 节表格 |
| 步骤 agent 停下来等待批准 | 配置的模式不是免确认模式 | 见 [安装与升级](安装与升级.md) 第 4 节，`npm run smoke -- check` 确认 |
| `req upgrade` 提示没有能支持本机 Paseo 的版本 | Paseo 升级到了 req-kit 还不支持的版本 | 等 req-kit 新版本；或暂时回退 Paseo 到 0.11.x |

还不能解决时，在对话中运行 `/req-doctor`，把输出交给维护者。
