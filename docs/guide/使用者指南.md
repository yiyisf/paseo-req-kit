# 使用者指南

req-kit 帮你把一个需求从"我想要……"做到"可以验收"：你在 Paseo 的对话里把需求讲清楚、确认一份需求说明，之后的方案设计、写代码、评审、测试和报告由一组 AI agent 在后台完成，结果发回同一个对话。

适合测试、产品经理、项目经理等不写代码、但熟悉需求和测试的同事。你不需要读代码，但可以随时查看每一步的产物，也可以亲自执行测试命令核对结果。

## 第一次使用之前

请开发同事确认这台机器已经装好 req-kit（`/req-doctor` 全部正常），并且项目已经接入：在项目根目录的对话中运行过 `/req-setup`，生成了项目说明和验证方法。测试同事熟悉项目的话，也可以自己运行 `/req-setup`。

## 提一个需求

1. **新建工作区**：在 Paseo 中点 **New workspace** → 选择项目 → **Isolation** 选 **New worktree** → 起点选主分支。每个需求一个工作区，几个需求可以同时进行，互不影响。
2. **输入 `/req` 和一句话**：例如 `/req 登录页增加短信验证码登录`。用 Pi 时输入 `/skill:req ……`。
3. **回答问题**：AI 会先复述它的理解，然后一次问一个问题，给出选项和推荐。它会问到异常情况、权限、已有数据、测试数据和验证环境，这些往往是你最清楚的。拿不准时可以说"你定"，它会采用推荐项并记为假设，最后请你过目。
4. **确认需求说明**：AI 给出一份 10 行以内的摘要，完整的需求说明在 `docs/features/<日期>-<名称>/spec.md`。确认后它会问是否开始开发。
5. **等待**：开发在后台进行，通常需要几个小时，不需要盯着。期间你会收到几句进展（方案定了、开始验证等）。

小改动（改文案、样式、一个配置项）会走快速流程：只问 2–3 个问题，开发环节各做一轮。

## 过程中

| 你想做的 | 在对话里说 |
| --- | --- |
| 看进度 | "做到哪了" |
| 暂停 | "先停一下"（当前步骤做到一半的工作不保留，已完成的步骤保留） |
| 继续 | "继续开发" |
| 改需求 | "我想改一下……"：先暂停，谈清变化的部分，更新需求说明（版本加 1，记入 `changes.md`）后继续，开发会在已有方案和代码的基础上只处理变化的部分。开发已经完成的也可以改 |
| 看看项目里有哪些需求 | "现在有哪些需求"：列出所有工作区中的需求和各自的阶段 |
| 接手别人的需求 | "这个需求之前是同事提的，现在什么情况"：讲清现状、待决事项和下一步 |

也可以不进对话，在终端里用 `req` 命令（需要开发同事装好并加入 PATH，见 [安装与升级](安装与升级.md)）：在项目目录中 `req list` 看所有需求，`req status` 看进度（多个需求时写名称的一部分，如 `req status sms-login`），`req stop`、`req resume` 暂停和继续。

每个步骤都会出现在这个对话的子 agent 列表里（名字形如"[20261012-sms-login] 6-代码评审 第2轮"），点开可以看到它在做什么。功能目录下的 `progress.md` 按时间记录了每一步的结果。

可能收到的通知（团队接入了企业 IM 的话，这些通知也会发到 IM）：

- **需要你决定**：方案审核发现只有你能回答的问题。AI 会逐个问你，然后继续。
- **等待批准**：某一步在等权限批准，按提示打开对应的 agent 处理，或请开发同事处理。
- **中断**：限流、网络中断这类临时问题会先自动等待重试，仍然不行才中断。AI 会说明原因和日志位置。环境类问题（例如测试服务没启动）你可以自己处理；涉及配置或代码的请开发同事处理。处理后说"继续开发"。

## 验收

完成后你会收到结论和摘要，完整报告在功能目录的 `report.md`：

- **验收对照表**：每条验收标准的结果，以及是怎么确认的（运行了什么命令、看到了什么、截图在哪里）。
- **需要你确认的决定**：开发过程中替你做的假设和取舍，以及被驳回的评审意见里会影响结果的那些。请逐条表态。
- **遗留问题**和**需要你做的事**。
- **用时与用量**：各步骤 agent 合计用了多长时间、多少 token、大约多少费用，便于估算后续需求的成本。

然后说"我要验收"。AI 会按验收标准一条一条带你核对：告诉你怎么操作、应该看到什么；能用命令验证的给出命令，你可以自己执行。每条结果记入功能目录的 `acceptance.md`。

- **全部通过**：请开发同事审阅代码并合并上线。流水线只做本地提交，不会自己合并或上线。
- **有不通过的**：逐项决定怎么处理：做得不对的，补进需求说明后继续开发；发现想要的不是这样的，按改需求处理；也可以接受现状并记下理由。

测试同事可以把验收标准直接转成测试用例：每条都写成了"前置条件 / 操作 / 预期结果"。

## 上线后发现问题

说"线上发现……不对"。AI 会先问这个问题是否正在影响真实用户：是的话，请马上联系开发同事或值班人员处理线上情况（req-kit 不碰生产环境）。然后它会问清现象、复现步骤、影响范围，关联到原来的需求，生成一份缺陷说明，按快速流程修复，修复后照常验收。

## 注意

- 一个对话只谈一个需求；对话过程中不要切换工作目录。
- 需求属于另一个项目时，到那个项目里新开对话。
- 遇到"未启动"或其他看不懂的情况，输入 `/req-doctor` 做一次体检，或请开发同事看一下。
