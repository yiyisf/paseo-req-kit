# 0015 需求变更后增量继续，而不是从零重做

- 状态：已采纳（细化 [0011](0011-resume-after-completion.md)：0011 决定"可以继续"，本条决定"怎么继续"）

## 背景

1.2 中 spec 改动或回答了需求方的问题后继续，是"从方案设计重新开始"：步骤 agent 拿到的提示与第一次相同，往往重新写一遍方案、重新审核全部代码，耗时接近第一次，还可能改掉已经验收过的部分。

## 决定

- 从方案设计继续时，状态中记录 `incremental`：接着第几次尝试、原因、本次开始时的提交、上一次是否已写过代码。
- 各步骤的提示附加 `engine/prompts/incremental.md`：方案在原文末尾追加"第 N 次尝试：需求变更"一节，只设计变化的部分；实现只改需要改的；代码评审只看本次开始以来的改动；验证重点验变化的验收标准，并回归其余的；报告说明这是第几次。
- `--restart` 仍是完全从零开始，不参考上次的方案和代码。

## 影响

变更后的继续通常比第一次快很多。增量的前提是上次的方案和提交还在分支上；如果分支被重置过，应使用 `--restart`。
