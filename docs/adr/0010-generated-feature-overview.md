# 0010 需求总览现场生成，不维护 INDEX.md

- 状态：已采纳

## 背景

设计方案计划在 `docs/features/INDEX.md` 中维护所有需求的一览。但每个需求在自己的 worktree 和分支上进行，如果每个分支都修改同一个提交进仓库的文件，合并时会反复冲突；而且一个工作区里看不到其他工作区尚未合并的需求。

## 决定

不提交 `INDEX.md`。`start-pipeline --list` 现场扫描这个仓库所有 worktree 中的 `docs/features/*/spec.md`、状态文件和验收记录，生成总览；同一需求出现在多个工作区时取最近更新的一份。`/req` 在路由、查看进度和接手时使用它。

## 影响

没有合并冲突，能看到所有工作区中的需求。代价是总览只在本机生成；不在这台机器上的工作区看不到。
