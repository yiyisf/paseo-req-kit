# 0012 评审小组：首轮并行评审，评审者核实汇总

- 状态：已采纳

## 背景

单一模型评审容易有固定的盲区；参考 pstack 的 `/interrogate`，多个模型独立评审能发现更多问题。但成员意见直接投票会放大误报，而且并行的成员在同一个目录里提交代码会互相冲突。

## 决定

- 配置 `reviewPanel` 开启，默认关闭；默认只用于标准档、方案审核和代码评审的第一轮。后续轮次只核对修复，用单个评审者。
- 成员并行运行，只读代码，各写一份意见文件到 `<功能目录>/review-panel/`，不提交、不写 `progress.md` 和 `decisions.tsv`。
- 配置的 `reviewer` 作为汇总者，逐条核实并归入"必须修改 / 建议修改 / 留给人决定 / 已驳回"四类；结论只依据核实后的"必须修改"，不按成员数量投票。被驳回和留给人决定的意见记入 `decisions.tsv`，最终报告展示。
- 部分成员失败时只汇总完成的成员；全部失败时该步骤失败。

## 影响

开启后每次评审多出 N 个 agent 的用量。汇总者的核实质量决定了效果，需要通过评估观察误报和漏报。
