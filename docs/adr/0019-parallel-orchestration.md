# 0019 用 Paseo 的并行子 agent：确认前独立审阅、方案提案

- 状态：已采纳

## 背景

Paseo 自带 `/paseo-advisor`（第二意见）、`/paseo-committee`（两个模型独立分析）等编排 skill。它们由聊天 agent 自由发挥，结果没有固定的去处，也不会稳定地写回需求文件；直接让 `/req` 调用它们还违反"入口不调用入口"（ADR 0008）。

## 决定

同样的思路由 req-kit 的引擎以固定的步骤实现，产物写进功能目录：

- **需求说明审阅**（`--spec-review`）：在需求方确认之前，由 reviewer（通常与对话用的不是同一个模型）在后台独立审阅草稿，写 `spec-review.md`，把问题写成带推荐的选择题；完成后通知对话，由对话 agent 核对后逐个问用户。不改 spec、不提交。默认只用于标准档（`specReview`）。
- **方案提案**（`designProposals`，默认关闭）：标准档的方案设计之前，几个 agent（默认 builder 和 reviewer）并行各提一份方案，方案设计步骤比较后决定，并在 `design.md` 中写"方案比较"。增量继续时不做。
- **浏览器验证**（`browserVerify`）：步骤 agent 有 Paseo 浏览器工具时，验证类步骤按验收标准在浏览器中实际操作。

Paseo 的编排 skill 仍然推荐使用者单独使用（例如对一个疑难问题请 `/paseo-committee`），文档中说明。

## 影响

确认前多一次几分钟的审阅，能在开发之前发现遗漏和歧义；方案提案以多一份方案的用量换取复杂需求的方案质量，所以默认关闭。
