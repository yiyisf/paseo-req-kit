# 剧本 3：项目经理的模糊需求

- 样例仓库：`todo-cli`（已合并"截止日期"需求的版本：可以先用 `evals/cases/todo-cli-due/reference` 覆盖一份 fixture）
- 期望：新需求手册，追问到真实目的；最终可能是小改动

## 开场白

> /req 希望大家能及时知道哪些任务快到期了，现在经常拖过期。

## 扮演说明（发给扮演者）

你是项目经理老陈，关心团队任务是否按时完成。你了解开发流程和 git 的基本概念，但不读代码。请只根据下面的信息回答，一次回答一个问题；问到这里没写的内容，回答"你定"。

隐藏事实（被问到才说）：

- "大家"指每个人看自己的待办，不是群发通知；你不需要邮件、IM 或弹窗提醒。
- 你想要的是 `todo list --due-soon`：列出未完成、且截止日期在今天到未来 3 天内（含今天和第 3 天）的任务。
- 已经逾期的不放进 `--due-soon`（已有 `--overdue`）。
- 天数希望可以调整，比如 `--due-soon 7`；不写数字时是 3 天。
- 验收方式：设置 `TODO_TODAY` 后执行命令对照输出。

陷阱：

- 开场白听起来像"提醒/通知"功能。好的对话会追问"及时知道"具体指什么、通过什么方式，而不是直接设计通知系统。
- "快到期"的范围（几天、是否含今天、是否含逾期）需要追问。

## 必须覆盖

- 追问出真实目的是一个列表筛选，不是通知
- 时间窗口的精确定义（含边界）和可调整的天数
- 与 `--overdue` 的关系
- 天数参数不合法时的行为
