# formatBytes 支持 TB、负数和小数位数

- 状态：已确认（2026-10-13）

- 类型：小改动
- 版本：1
- 格式：req-kit/spec@1

## 1. 背景与目标

报表里出现了超过 1024 GB 的数值，目前显示为"2048 GB"；差值列可能为负数，目前会直接报错。

**目标**：大数值显示为 TB；负数正常显示；调用方可以指定小数位数。

## 3. 范围

**本次要做**
- 支持 TB 单位、负数、小数位数参数

**本次不做**
- PB 及以上单位；本地化（如中文单位名）

## 5. 功能需求与验收标准

### FR-1 支持 TB（优先级：必须有）

- **AC-1.1** `formatBytes(1024 ** 4)` 返回 `"1 TB"`。
- **AC-1.2** `formatBytes(1.5 * 1024 ** 4)` 返回 `"1.5 TB"`。
- **AC-1.3** 超过 1024 TB 时仍用 TB：`formatBytes(2048 * 1024 ** 4)` 返回 `"2048 TB"`。

### FR-2 支持负数（优先级：必须有）

- **AC-2.1** 负数按绝对值换算后加负号：`formatBytes(-1536)` 返回 `"-1.5 KB"`，`formatBytes(-1)` 返回 `"-1 B"`。
- **AC-2.2** `NaN`、`Infinity`、`-Infinity` 和非数字仍然抛出 `TypeError`。

### FR-3 小数位数（优先级：必须有）

- **AC-3.1** 第二个参数 `{ decimals }` 指定保留的小数位数，默认 1。`formatBytes(1536, { decimals: 2 })` 返回 `"1.50 KB"`；`formatBytes(1536, { decimals: 0 })` 返回 `"2 KB"`。
- **AC-3.2** 只有使用默认值（未传 `decimals`）时才去掉末尾的 `.0`：`formatBytes(1048576)` 仍然返回 `"1 MB"`；`formatBytes(1048576, { decimals: 1 })` 返回 `"1.0 MB"`。
- **AC-3.3** 以字节为单位（小于 1024）时不显示小数：`formatBytes(512, { decimals: 2 })` 返回 `"512 B"`。
- **AC-3.4** `decimals` 不是 0 到 3 之间的整数时抛出 `RangeError`。

### FR-4 现有行为不变（优先级：必须有）

- **AC-4.1** 现有测试中与本需求无关的断言继续通过。现有测试里"`formatBytes(-1)` 抛出 TypeError"一条与 FR-2 冲突，按 FR-2 修改。
