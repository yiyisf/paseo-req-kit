req-kit从一句需求，到可验收的功能

在 Paseo 中用对话把需求谈清楚，由一组 AI agent 在后台完成方案设计、代码实现、评审和验证，结果发回同一个对话。

GitHub

对话对齐需求

一次一个问题，给出选项和推荐；把异常情况、权限、测试数据都问到。确认前还会请另一个模型独立审阅需求说明。

后台 agent 流水线

方案设计、实现、评审、验证、报告依次由不同的 agent 完成；缺陷先复现再修、重构先锁住行为、评估只调研不写代码，大需求按切片逐片实现。

质量门，如实报告

流水线自己运行项目的 lint、测试、构建，改坏了发回修复；做事的和检查的分开，结论只看结果文件和证据，遗留问题如实写进报告。

分阶段提测

研发完成写好提测说明，可以停下来交给测试同事，在测试环境中验证；发现缺陷可以退回研发，修完再提测。

用好 Paseo

复用 Paseo 的 agent profile、paseo.json 服务和 worktree、定时任务与内置浏览器；几个需求可以并行，前后端分仓的需求可以作为联合需求，每个仓库一个工作区同时开发。

安全边界清楚

只做本地提交，不合并、不推送、不上线；不连接生产环境，测试环境说明里只写口令在哪里取。

一个需求，四个阶段

你负责把需求讲清楚和最后验收，中间的工作交给 agent。

01

对话对齐需求

输入 /req 和一句话。AI 先复述理解，再一次问一个问题、给出选项和推荐，最后写成一份需求说明请你确认。

02

后台开发

方案设计、方案审核、代码实现、代码评审、修复，由一组 agent 在后台完成。每一步都挂在你的对话下，可以随时点开看。

03

提测与验证

研发完成写好提测说明。可以接着自动验证，也可以停下来交给测试同事，在测试环境里验证。

04

逐条验收

收到结论和报告后，AI 按验收标准一条一条带你核对，记录结果。合并上线仍然由人决定。

流水线

做事的和检查的是不同的 agent，每一步只看文件、不靠记忆；审核、评审、验证不通过就返工，轮数有上限，遗留问题如实写进报告。

安装

在运行 Paseo daemon 的机器上执行一条命令：检查环境、安装、装好 /req 等 skill、引导你选择 agent。再次运行即升级。

npx -y paseo-req-kit@latest install

只需要 Node.js 22+。公司内网只有 npm 镜像时：npx -y --registry=<镜像地址> paseo-req-kit@latest install（会保存为本机的 npm 源）。beta 版把 latest 换成 beta。
